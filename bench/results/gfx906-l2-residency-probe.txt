# L2 residency for the decode hot set - three independent reasons the lever cannot pay on this card
# tools/hip/gfx906_l2_probe.cpp, one MI50 (gfx906), card exclusive.

device: AMD Instinct MI60 / MI50, 60 CU
L2 cache: 8.00 MiB                      (not the 4 MiB the discussion assumed for MI50)
hipDeviceAttributePersistingL2CacheSize      -> not in this HIP header
hipDeviceAttributeMaxPersistingL2CacheSize   -> not in this HIP header

# 1. no API.  TheRock ROCm 10.3's HIP headers carry no persisting-L2 attribute and no access-policy-window type,
#    so there is nothing to set: this is the CUDA-only surface (cudaAccessPolicyWindow / cudaLimitPersistingL2-
#    CacheSize) with no HIP equivalent on this stack.  A policy the runtime does not have cannot be a lever.
#
# 2. the hot set does not fit anyway.  Decode picks 10 of 512 experts per layer, and a TQ2_T expert blob is
#    1.31 MB, so one layer's picks are 13.1 MB against 8 MiB of L2 - a window could pin at most a fifth of one
#    layer, and 48 layers are live per token.
#
# 3. the kernel is not cache-limited in this shape.  The engine's own decode GEMV (one 64-lane wave a row,
#    K 2560) against growing weight footprints:
#
#     footprint   rows   ms/pass     GB/s
#        1.0 MiB    102    0.0164     63.6
#        2.0 MiB    204    0.0149    139.8
#        3.0 MiB    307    0.0173    181.6
#        4.0 MiB    409    0.0216    194.3
#        6.0 MiB    614    0.0249    252.9
#        9.0 MiB    921    0.0340    277.1
#       13.1 MiB   1341    0.0355    386.6      <- one layer's hot set
#       26.2 MiB   2682    0.0590    465.4
#       52.4 MiB   5365    0.0919    597.9
#
#    Bandwidth RISES with the footprint instead of falling off past L2: at 1-4 MiB there are only 102-409 rows to
#    issue (a handful of blocks per CU), so those shapes are occupancy-limited, not cache-limited.  Nothing here
#    is waiting on HBM for a footprint that would fit in L2 - the opposite of what a residency policy would fix.

# verdict: not implemented.  Recorded so the next person does not spend a round on it: on this stack there is no
# API, the working set is 1.6x the L2, and the GEMV curve shows no cache cliff to exploit.
